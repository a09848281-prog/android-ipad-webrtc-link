# WebRTC Link v2 — 実装計画・受け入れ条件

## 方針
- 安定版 `android-native-stable-v1` と既存PWAを変更せず保護する。
- このブランチ `feature/full-webrtc-controls-v2` で段階実装する。
- AndroidはGalaxy A22 5G / Android 13 (API 33)を主対象、iPadはSafari/PWA。
- シグナリングは既存GASプロトコルを維持し、映像・音声はWebRTC P2P。
- 既存のP2P双方向映像・音声の成功状態を回帰テストの基準にする。
- 画面共有、写真撮影、録画、ファイル転送は実装しない。

## 要求機能
### 接続
- 接続状態・経過時間・再接続状態の表示
- ICE/PeerConnection状態を監視し、切断時は段階的に再接続
- RTT、送受信bitrate、packet lossをRTC統計から取得（取得不能値は「未対応/不明」と表示）
- 接続/切断通知、ローカル/リモート切断の対称処理
- ペアリング済み端末のみ接続可能にする明示的な端末登録・承認
- 接続前の権限・ネットワーク・GAS疎通チェック

### カメラ・音声
- カメラプレビュー、前後カメラ切替、対応端末でのズーム/ライト
- 解像度/FPSプリセットと対応モード確認
- 送信VideoTrackの安全な差し替えと旧Capturer/Sourceの解放
- ネットワーク品質に応じた送信bitrate/解像度の段階調整
- マイクミュート、受信音量（ブラウザ/OSが許す範囲）、音声のみ/映像のみ

### iPad管理
- 登録Android複数台、表示名、お気に入り、接続履歴、最終接続時刻
- オンライン状態はheartbeatの有効期間内だけ表示
- バッテリーはAndroidが明示的に共有した値のみ表示。取得不能時は非表示

### Androidバックグラウンド
- 適法なForeground Serviceと常駐通知
- 通知から切断、プロセス再生成時の状態再確認
- バッテリー最適化の案内、緊急切断
- AndroidのOS/メーカー制限による停止可能性をUIに明記

### 位置情報（厳格なワンショット）
- iPadの「位置情報を見る」ボタンを押したときだけ要求を送る
- AndroidでOSの位置情報権限を要求し、許可時のみ現在地を一度返す
- 自動取得、タイマー取得、バックグラウンド取得、位置履歴保存は禁止
- 拒否/タイムアウト/位置情報無効/利用不可を区別して表示
- 切断・画面終了時に一時座標を破棄し、監査ログに座標を含めない

## 実装順
1. クラッシュ要因修正とビルド再現性（ACCESS_NETWORK_STATE、CI）
2. 双方向切断・状態遷移・統計・再接続の基盤
3. AndroidのMediaTrack制御（カメラ切替/品質/ミュート/ライト/ズーム）
4. Foreground Serviceの通知操作・復帰・端末情報
5. iPad UIと端末登録/複数台管理
6. iPadボタン起点の位置情報ワンショット
7. 実機試験、回帰試験、利用可能機能の明示

## 安全条件
- 位置情報権限は必要になった時だけ要求し、常時位置権限を追加しない。
- ペアリング前の自動接続や第三者からの無確認接続を許さない。
- GAS URL/鍵/認証情報をソースへ埋め込まない。
- どの機能もAPI非対応時に成功したように表示しない。

## 受け入れテスト（各段階で実施）
1. Galaxy A22 Android 13で起動・権限許可・P2P接続がクラッシュしない。
2. Android→iPad映像/音声、iPad→Android音声が従来どおり届く。
3. ローカル/リモート双方の切断でカメラ・マイク・PeerConnection・タイマーが解放される。
4. Wi-Fi切断/復帰で状態表示と再接続が整合する。
5. カメラ切替後も送信映像が継続し、旧カメラが解放される。
6. 位置情報はiPadボタン押下時のみ要求され、拒否時に座標を返さない。
