# WebRTC Link v2 受け入れテスト

> v2テスト版APKは `jp.a09848281.webrtclink.v2test` としてインストールされ、既存の安定版アプリを上書きしません。v2側で端末ペアリングを改めて行ってください。

この文書は、GitHub Actionsのビルド成功と実機での動作確認を分けて記録するための手順です。

## 1. 初回セットアップ

1. GitHubの `gas/Code.gs` 全体を既存GASプロジェクトへ貼り付けて保存します。
2. GASを「新バージョン」で再デプロイします。既存の `/exec` URLを維持してください。
3. Androidアプリを起動し、GAS URLを設定します。
4. Androidで「位置情報の許可を設定」を必要な場合に設定します。WebRTC開始前に許可しておいてください。位置情報用Foreground ServiceタイプやACCESS_BACKGROUND_LOCATIONは使用しません。
5. Androidで「iPadとペアリング」を押し、8桁コードを発行します。
6. iPadのPWAで同じGAS URLを保存し、8桁コードを入力して端末登録します。
7. Androidで「WebRTCを開始」を押します。iPadの端末一覧でオンライン状態・電池・通信方式・接続コードを確認し、「Androidに接続」を押します。

## 2. 機能テスト

- [ ] 登録済みAndroid端末が複数台一覧に表示される
- [ ] 端末名変更・お気に入り・登録解除が動作する
- [ ] 登録解除でサーバー側認証トークンも失効する
- [ ] オンライン・オフライン状態が更新される
- [ ] 電池残量・通信方式が表示される
- [ ] 接続成功後に最終接続時刻と接続履歴が保存される
- [ ] 双方向の映像・音声が動作する
- [ ] Androidのマイクミュート・映像停止・前後カメラ切替が動作する
- [ ] Androidの360p/720p/1080pと15/24/30fps設定が適用され、非対応設定時に前の画質へ戻る
- [ ] iPadのマイクミュート・映像停止・相手音量・PTTが動作する
- [ ] iPadの通信統計（時間・RTT・bitrate・packet loss）が更新される
- [ ] iPadの接続前診断でGAS・WebRTC・STUN状態が表示される
- [ ] iPadで「位置情報を見る」を押したときだけAndroidの位置情報が1回返る
- [ ] 位置情報の許可拒否・位置サービスOFF・タイムアウト時にエラー表示される
- [ ] 位置情報結果を受信後、GASのone-shotメッセージが専用一時キュー（最大30秒）に入り、認証済み相手の最初のポーリング時に削除される
- [ ] iPadの切断ボタンとAndroid通知の停止操作で双方が終了する
- [ ] Android画面ロック中に通知が維持され、通信が継続する

## 3. Android 13 / Galaxy A22で確認すること

- Android 13（API 33）でインストール・起動できる
- カメラ・マイク権限を拒否した場合に安全に停止する
- 通知権限を拒否した場合の表示と動作を確認する
- バッテリー設定を「制限なし」にした場合と標準設定の場合を比較する
- 画面ロック、アプリ切替、Wi-Fi切替、モバイル通信切替、電波断を試す
- 端末の発熱とバッテリー消費を確認する

## 4. 制約・未保証事項

- GitHub ActionsのGradleビルド成功は、実機でのカメラ・マイク・P2P・バックグラウンド動作成功を意味しません。
- AndroidのForeground Serviceでも、メーカー独自の省電力制御・強制停止・ユーザーの強制終了を越えて常時動作する保証はありません。
- ICE再起動は上限付きの試行です。TURNサーバーがないため、対称NATなど一部ネットワークではP2P接続できません。
- iPad Safariのズーム・ライト・音量制御はブラウザAPI対応に依存します。
- Android native版のズーム・ライト・カメラ自動画質調整は未実装です。Android nativeは解像度/FPS・カメラ切替・マイク/映像ON/OFFを対象にしています。
- 位置情報は前景権限のみで、ACCESS_BACKGROUND_LOCATIONは要求しません。GASに位置情報履歴を作らず、one-shotメッセージは最初のポーリングで消費します。
- ペアリングトークンはGAS Script Propertiesにハッシュで保存します。iPadのブラウザ保存領域にはトークンが保存されます。試作版であり、公開サービス用途には追加のセキュリティレビューが必要です。
- 画面共有・写真撮影・録画・ファイル転送は対象外です。
