# GAS更新手順（WebRTC Link v2 / 認証対応）

今回の端末ペアリング・認証、端末状態確認、ワンショット位置情報、切断通知を使うには、GitHub上の `gas/Code.gs` の変更を既存GASプロジェクトへ反映する必要があります。GitHub Pagesを更新しただけでは、公開済みGASは自動更新されません。

## 手順

1. GitHubの [gas/Code.gs](../gas/Code.gs) を開き、内容をすべてコピーします。
2. 既存のGoogle Apps Scriptプロジェクトを開きます。
3. 左側の `Code.gs` を開き、既存コードをすべて置き換えて保存します。
4. 右上の「デプロイ」→「デプロイを管理」を開きます。
5. 既存のウェブアプリデプロイの編集（鉛筆アイコン）を押します。
6. バージョンを「新バージョン」にしてデプロイします。
7. ウェブアプリURLが従来と同じ `/exec` URLであることを確認します。URLが変わった場合はAndroidとiPadの両方で新しいURLを設定します。

## 変更点

- `pair_start` / `pair_complete`：Androidが発行した8桁・5分間・1回限りのコードでiPadと端末をペアリング
- 端末ごとの認証トークン：Script PropertiesにはSHA-256ハッシュを保存し、シグナリングとポーリングを認証
- `device_status`：Androidのオンライン状態・電池残量・通信方式・現在の接続コードを一時キャッシュ（約65秒）
- `unpair`：登録解除時にサーバー側の認証トークンを失効
- `hangup`：相手側への切断通知
- `location_request`：iPadからAndroidへのワンショット位置情報要求
- `location_result`：許可済みAndroidからの1回限りの座標応答
- `location_denied` / `location_error`：拒否・取得失敗の応答

## 位置情報のプライバシー

- Androidアプリの「位置情報の許可を設定」ボタンはOS権限を設定するだけで、位置情報を取得しません。
- 実際の位置情報取得は、iPadで「位置情報を見る」を押して要求した場合だけです。
- Androidの位置情報許可は、Androidアプリの「位置情報の許可を設定」からOSの許可画面で設定します。Foreground Serviceにlocationタイプは追加せず、ACCESS_BACKGROUND_LOCATIONも要求しません。
- `ACCESS_BACKGROUND_LOCATION` は要求しません。位置情報は一度限りの要求時だけ取得し、GASは位置情報メッセージを最初のポーリングで消費します。
- 位置情報の履歴保存や自動取得は行いません。
- 許可されていない場合、Androidは座標を送信せず拒否応答を返します。

## 注意

GASは接続情報の中継のみを行います。カメラ・マイクのメディアや位置情報をGASへ保存する設計ではありません。現行シグナリングは6桁ルームコードと端末別トークンを利用する試作仕様です。一般公開・高機密用途に必要な多要素認証、端末紛失時の運用、レート制限強化などは別途セキュリティレビューが必要です。公開URLを知る第三者への完全な防御が必要な用途には使用しないでください。

## 初回ペアリング手順

1. GASを新バージョンでデプロイします。
2. Androidアプリを起動し、同じGAS `/exec` URLを入力します。
3. Androidで「iPadとペアリング（8桁コード発行）」を押します。
4. 表示されたコードをiPadの「登録済みAndroid端末」欄に入力して「端末登録」を押します。
5. iPadに端末が保存され、オンライン状態が確認できるようになります。
6. Androidで「WebRTCを開始」し、iPadで登録端末を選んで「Androidに接続」を押します。

## 認証・保存について

- 認証トークンはAndroidのアプリ設定とiPadのブラウザ内ストレージに保存されます。
- GASのScript PropertiesにはトークンのSHA-256ハッシュを保存します。
- 8桁ペアリングコードは5分で失効し、1回だけ使用できます。
- iPadの「登録解除」はGAS側のトークンも失効させます。同じ端末を別のiPadで使っている場合、その登録も再ペアリングが必要になります。
- 端末のオンライン状態は約65秒間の一時キャッシュです。常時監視や位置履歴は行いません。
- この試作版は個人利用向けです。認証トークンを含むJSONPのGET要求が発生するため、公開サービスや高い機密性が必要な用途には追加のセキュリティ設計が必要です。
